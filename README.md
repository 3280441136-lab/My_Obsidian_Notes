# 我的嵌入式知识库

## 知识库结构

```
📕我的嵌入式知识库/
├── 💻软件设计/        ← 外设驱动配置、RTOS、C语言、Git
├── 🧠MCU底层原理/      ← 芯片架构、寄存器级硬件原理
└── 🔧硬件设计/        ← 板级电路、元器件、PCB设计
```

## 添加内容原则

### 笔记属性
每篇笔记必须包含 YAML frontmatter：
```yaml
---
version: V1.0
updated: YYYY-MM-DD
author: RUI
tags: [软件|MCU底层|硬件]
---
```
- `version`：笔记版本号
- `updated`：最后更新日期
- `author`：固定为 RUI
- `tags`：知识大类标签，用于图谱颜色分组<br>
  `软件` = 💻软件设计 / `MCU底层` = 🧠MCU底层原理 / `硬件` = 🔧硬件设计

### 笔记风格
- 标题层级不使用数字序号（不用 `1.`、`1.1` 等）
- 开头不写"适合对象""学习目标"段落，开门见山
- 每篇笔记应有简洁的目录
- 正文使用人话解释，配合代码示例和速查表
- 末尾附"相关笔记"段落，只链接有实质关联的笔记

### 内容组织
- **同类内容合并到一个 md**，不按厂商拆分（如 GPIO.md 覆盖所有厂商，不拆成 GPIO-ST.md、GPIO-GD.md）
- 不同厂商的实现差异在同一个文件内用标题层级区分，相同点优先后写差异
- 笔记应自底向上：先讲基础概念，再讲具体配置，最后附模板和避坑

### 链接原则
- **只链接有实质关联的笔记**，不滥用链接
- 保持 Obsidian 关系图谱清晰，不形成无意义的密集连线
- 硬件设计和软件设计的链接应该很苛刻，除非有很大关系，否则不链接。
- 不同大类间谨慎链接（如 C语言基础 不需要链接到 LDO 选型）

### 更新流程
1. 新知识先记录在 `💬与AI的对话（未整理进知识库）/`
2. 对话原文仍保留在 `💬与AI的对话/` 中，作为原始记录备查
3. 定期回顾，将对话内容**分割、提炼、合并**到对应知识区
4. 如果要更新的笔记内容不全或干货不足，请你自行补充，并在补充前询问我
5. 每篇笔记独立成文，不依赖对话上下文
6. 笔记更新后注意修改和清楚死链接，保证关系图谱的正确。
7. 更新后修改 `updated` 日期

### 命名规范
- 文件夹用 `Emoji + 中文名` 格式
- 笔记文件用 `中文名.md`，清晰表达内容
- 不使用空格和特殊符号（Emoji 除外）
