# 分级应急智显播控终端：项目定向说明书

## 这份文档回答什么

这不是开发清单，也不是学习计划。它用于在整个参赛过程中反复回答五个问题：

1. 赛题真正要求我们做什么？
2. 为什么我们不把作品做成普通图片播放器？
3. 每一项功能在产品中解决什么问题，而不只是为了“凑功能”？
4. 我们的技术边界在哪里，哪些事情现在不值得做？
5. 一个有机会冲击更高奖项的最终作品，应当呈现出怎样的完整性？

文中“目标”描述的是本项目拟实现的最终状态，不代表当前已经完成；只有最终实板、同一固化镜像上的效果才能作为参赛成果主张。

## 一、赛题给出的边界

### 1. 开发平台

赛题指定使用 **HX4S20C 开发板**，核心器件为安路 **EG4S20BG256** FPGA。板卡的重要资源包括：

- 约 \(19{,}600\) 个 LUT 和 \(19{,}600\) 个触发器；
- 板载 SDRAM：\(2\mathrm{M}\times32\mathrm{bit}=8\,\mathrm{MiB}\)；
- 板载 TF 卡槽、双 HDMI 接口、按键、拨码开关、数码管、LED、QSPI Flash 与 SPI Flash；
- 可用 PLL、片上 RAM 和 FPGA I/O 构成多时钟、多数据流系统。

赛题允许连接外围电路或功能模块，但**不能增加额外处理器**，包括不能把控制或算法预处理交给单片机、树莓派等设备。作品展现出的图像处理、控制逻辑和数据通路，应由 FPGA 自主完成。

### 2. 基础要求

基础要求不是“选做功能”，而是作品进入评审的地基：

| 赛题基础项 | 明确要求 | 对本作品意味着什么 |
|---|---|---|
| BMP 读取与 HDMI 显示 | 通过 SPI 从 TF 卡读取 \(640\times480\)、\(24\)-bit RGB 非压缩 BMP，解析后写入 SDRAM，通过 HDMI 实时显示 | 建立从素材存储到显示器的完整图像数据通路 |
| 切换与轮播 | 支持按键手动切换、自动轮播，画面连续稳定、无明显闪烁或异常 | 产品具备日常信息展示能力，而不是只能显示一张图 |
| HDMI 音频 | 输出 \(48\,\mathrm{kHz}\) 音频测试音，实现音视频同步播放 | 产品拥有与画面联动的声音通路 |
| 稳定运行 | 固化至开发板，上电即可运行 | 作品是独立终端，而不是依赖电脑现场“启动”的演示程序 |

### 3. 扩展要求

官方列出五个扩展方向。它们没有逐项固定分值，评委会综合考察完成数量、难度、质量、稳定性和演示效果：

| 编号 | 官方扩展方向 | 赛题真正期待看到的能力 |
|---|---|---|
| 1 | 图层叠加与字幕效果 | 多图层合成、动态文字、信息展示能力 |
| 2 | 图片切换与转场特效 | 帧缓存管理和连续切换能力 |
| 3 | 图片缩放适配 | 根据 BMP 宽高处理不同尺寸素材的能力 |
| 4 | 实时调节与 OSD 信息叠加 | 用户交互、实时像素处理和可观察的系统状态 |
| 5 | 音频可视化 | 音频数据处理与视频渲染联动能力 |

官方给出的评审导向很清楚：稳定完成一项扩展可以获得一定加分；完成两项且效果良好可获得扩展部分较高分；完成三项及以上且完成度较高可获得更高分；完成度和创新性突出时才有机会接近满分。因而，高分不是“写出最多模块”，而是让多个模块在一个完整系统中稳定协同。

### 4. 官方实现指导给出的起点

官方例程已经覆盖以下底座：

\[
\text{TF 卡 BMP}
\rightarrow
\text{FIFO}
\rightarrow
\text{SDRAM 帧缓存}
\rightarrow
\text{HDMI 图像输出}
\]

以及 HDMI 音频测试音输出。官方进一步建议：用双帧缓存和 Alpha 渐变完成淡入淡出；用 OSD 叠加文字；用 BMP 文件头获得宽高并进行缩放；用音频 PCM 驱动 FFT/DFT 频谱显示。这意味着我们的工作不是从零发明 HDMI 和 SDRAM，而是基于可靠底座，把作品做成有明确应用逻辑的系统。

## 二、我们选择的开发方向

### 1. 不是“相册播放器”，而是离线应急信息终端

我们选择的使用场景是：展馆入口、厂区通道、公共大厅等长期显示宣传、路线与安全信息的位置。

普通图片轮播是这种设备的日常工作；但真正需要展示系统快速、稳定响应的时刻，是发生注意事件或紧急事件时。因此，我们不另换一个与赛题无关的场景，而是将赛题原本列出的“应急信息发布”场景做深：

\[
\text{普通信息轮播}
\rightarrow
\text{事件输入}
\rightarrow
\text{FPGA 判断优先级与区域}
\rightarrow
\text{告警画面、字幕、声音、频谱联动}
\rightarrow
\text{事件解除后的平滑恢复}
\]

比赛现场可使用板载按键或 GPIO 电平模拟外部事件；在实际部署中，这些 GPIO 可连接报警干接点或其他逻辑输入。外部输入只提供“发生了什么”的电平信号，如何判断优先级、选择画面、生成字幕和控制输出，仍全部由 FPGA 完成。

### 2. 作品名称

**分级应急智显播控终端**

名称中的“分级”不是营销词，而是作品最重要的产品逻辑：不同等级事件不能被同等对待；不同区域事件也不能显示同一张泛泛的告警图。

### 3. 作品简介

> 本作品面向展馆、厂区和公共通道的离线应急信息发布场景，设计一套分级应急智显播控终端。系统以安路EG4S20 FPGA为核心，在无额外处理器条件下，从TF卡读取并解析BMP图片，利用SDRAM双帧缓存和HDMI完成稳定图像与提示音输出。常态下系统自动轮播宣传和引导页面；当板载按键或GPIO事件输入触发注意、紧急等级时，优先级状态机在帧边界切入对应分区的疏散路线、滚动告警和提示音，事件解除后平滑恢复常态。显示通路集成多图层Alpha混合、淡入淡出转场、不同分辨率图片缩放适配、亮度与对比度调节及OSD信息叠加；同步复用音频PCM完成定点频谱渲染，实现音画联动。系统具备TF读取异常提示与内部告警界面兜底，可固化至板载Flash上电运行，突出FPGA低延迟、确定性和高可靠性。

这段简介的重点不是宣称“算法很复杂”，而是完整说明了：使用者在哪里用、输入什么事件、产品如何决策、屏幕和声音如何响应、异常时如何避免失效，以及 FPGA 在其中承担什么工作。

## 三、产品逻辑：它在真实场景中怎么工作

### 1. 三种工作状态

| 状态 | 用户看到的结果 | 产品意义 |
|---|---|---|
| 普通模式 | 正常轮播宣传、安全须知和路线图片；可手动切图、调节显示参数 | 满足日常公共信息展示 |
| 注意模式 | 保留背景内容，在顶部或底部加入黄色滚动提醒、状态图标和提示音 | 对非立即疏散事件给出醒目但不破坏主要信息的提醒 |
| 紧急模式 | 以转场切入红色告警页面，显示对应分区的疏散路线、滚动指令和高优先级提示音 | 对紧急事件提供直接、明确的行动指引 |

它们的优先级关系必须固定：

\[
\text{紧急模式} > \text{注意模式} > \text{普通模式}
\]

例如，当系统正在播放普通信息时，紧急区域 A 输入到来，系统不等待本轮图片播放结束，而是在安全帧边界切换到区域 A 的路线图；若同时出现注意级输入，紧急画面仍保持优先。这种可预期的行为，是“播控终端”区别于普通播放器的地方。

### 2. 分区的意义

若所有事件都只显示“请注意安全”，作品的应急场景仍然很弱。分区应急的做法是预置至少两套路线资源，例如区域 A 和区域 B：

- 区域 A 事件：显示“请向东侧出口疏散”的路线页；
- 区域 B 事件：显示“请向西侧出口疏散”的路线页；
- 普通模式：显示常规路线、安全宣传或展馆介绍。

这样，按键/GPIO 不是普通的“下一张图片”按键，而是模拟不同的外部事件。评委可以直观看到输入变化如何改变输出决策。

### 3. 不黑屏的原则

成熟产品不能把 TF 卡视为永远正确。若未插卡、读取超时、图片格式错误或素材缺失，系统至少应显示由 FPGA 内部 OSD 生成的故障/告警页面，而不是停在黑屏。这个功能不属于官方五个扩展的某一项，却直接体现工程鲁棒性和产品可用性。

## 四、赛题项与本作品功能的一一对应

### 1. 基础项如何成为产品底座

| 赛题要求 | 本作品的功能选择 | 为什么这样做 |
|---|---|---|
| TF 卡 BMP 读取、解析、SDRAM、HDMI | 从 TF 卡加载普通、注意、紧急分区路线等 BMP 素材，写入 SDRAM 后由 HDMI 输出 | 所有页面都走同一条真实数据通路，避免用固定 ROM 图像“伪装”播放器 |
| 手动切换与自动轮播 | 普通模式支持轮播和手动查看；事件发生时由优先级控制器打断轮播 | 同一套播放器同时覆盖日常展示与事件响应 |
| HDMI 音频输出 | 生成不同模式的提示音，并输出到 HDMI | 声音成为事件等级的一部分，而非孤立测试项目 |
| 上电稳定运行 | 配置固化至板载 Flash，上电后完成初始化并进入普通模式或故障提示 | 证明它是独立终端，不依赖电脑 |

### 2. 扩展项如何服务于同一产品

| 赛题扩展项 | 我们选择的实现 | 在产品中的作用 |
|---|---|---|
| 图层叠加与字幕 | OSD 显示滚动告警、模式、区域、参数、图标和频谱 | 一张背景 BMP 被转化为可传达实时状态的信息页面 |
| 转场特效 | SDRAM 双帧缓存、Alpha 淡入淡出 | 事件切入和恢复过程连续，避免硬切画面造成的突兀和闪烁 |
| 缩放适配 | 解析 BMP 宽高，支持多种明确尺寸图片按比例居中缩放至 HDMI 输出 | 让不同来源的路线图、宣传图可复用，不受单一尺寸限制 |
| 实时调节与 OSD | 按键/拨码调整亮度、对比度，OSD 显示当前参数 | 展示 FPGA 对输出像素的实时处理能力，也适应不同现场光照 |
| 音频可视化 | 复用 HDMI 音频 PCM，进行定点频谱分析并绘制频谱柱 | 让声音数据真实参与画面生成，体现音画融合 |

### 3. 两个核心技术关系

双帧淡入淡出不是装饰，它解决“显示时不能同时破坏当前画面”的问题。每个颜色分量可按下面关系组合：

\[
C_{\mathrm{out}}
=
\bigl(\alpha C_{\mathrm{new}}+(16-\alpha)C_{\mathrm{old}}\bigr)\gg4
\]

缩放适配不是只修改显示文字，而是从输出像素坐标反查源图坐标：

\[
x_s=\left\lfloor\frac{x_oW_s}{W_o}\right\rfloor,
\qquad
y_s=\left\lfloor\frac{y_oH_s}{H_o}\right\rfloor
\]

先完成可验证的最近邻缩放，使多尺寸图片真正能显示；如果在系统整体稳定、资源和带宽有余量时再实现双线性插值，则属于画质加分，不应反过来影响基础功能的完成度。

## 五、从单片机基础到 FPGA 项目的真正变化

单片机项目通常是“读取一个输入，计算，再输出一个结果”的顺序式程序。这个作品则更像几条长期同时运行的数据通路：

- TF 卡按自己的速度提供文件数据；
- SDRAM 在另一个时钟下接收或提供成批像素；
- HDMI 必须严格按像素时序持续取数，不能等待；
- OSD、转场、亮度对比度和频谱要在每个输出像素到来时完成；
- 音频还需要稳定地以固定节奏输出。

因此，最难的不是“写一个函数”，而是让每个模块在自己的时钟下稳定工作，并通过 FIFO 可靠交接数据。FIFO 可以理解为两个不同速率模块之间的缓冲仓：上游写得快时暂存数据，下游读取时持续供给；它不是为了增加功能，而是为了避免 HDMI 因等待 TF 卡或 SDRAM 而中断。

对本项目而言，真正必须接触的技术领域是：

1. Verilog/时序逻辑、复位与状态机；
2. 时钟规划、跨时钟域与 FIFO；
3. SPI/TF 卡、BMP 文件格式和像素数据组织；
4. SDRAM 帧缓存与读写仲裁；
5. HDMI 视频时序和 HDMI 音频数据通路；
6. 图层合成、定点数运算、缩放、Alpha 混合、亮度/对比度；
7. 定点 FFT/DFT 或等价频段能量计算与图形渲染；
8. 配置固化、上电初始化和异常处理。

## 六、怎样的完成方式更有机会获得高奖项

奖项无法提前保证，但高分作品通常不是“单项很多、现场分别演示”，而是同时做到以下几件事。

### 1. 基础项必须成为不需要解释的事实

评委应能在上电后直接看到：TF 图片能连续稳定显示；按键切换与轮播正常；HDMI 有声音；拔掉电脑仍能自动运行。基础项一旦不稳定，后续扩展很难发挥价值。

### 2. 五项扩展不应各自孤立

最有说服力的画面是：普通轮播时可以显示 OSD 与频谱；触发紧急区域事件后，画面通过淡入淡出进入对应路线，字幕、音效和频谱同步变化；现场光线改变时调节亮度和对比度；不同大小路线图仍能正确显示。此时每一项扩展都在同一条产品逻辑中发挥作用。

### 3. 创新应当可观察、可解释、可验证

本项目的创新不依赖模糊的“智能”描述，而是三件可验证的事：

- **分级：** 紧急事件必然抢占注意和普通显示；
- **分区：** 不同事件输入得到不同路线内容，而不是同一张告警图；
- **兜底：** 素材或 TF 卡异常时系统有明确安全输出，不黑屏。

这三件事使作品从“多媒体展示系统”变成“可部署的应急信息终端”。

### 4. 鲁棒性是最容易被忽略、也最容易拉开差距的地方

高完成度不是只在一次成功运行时录下视频，而是能够重复上电、连续轮播、频繁触发事件、切换不同图片、处理异常输入，仍不花屏、不死机、不依赖电脑。双帧缓存、帧边界切换、FIFO、状态机优先级和故障页，都是为这一点服务。

### 5. 资源和范围必须有节制

不把 MP4 解码、网络协议、摄像头识别、双屏联动等高风险功能塞进首个完整版本。它们看起来“更大”，却会分散资源和调试时间，也不一定比一个稳定、闭环、可解释的应急终端更有分数价值。

更合理的最终目标是：

\[
\boxed{
\text{基础功能完整}
+
\text{五项扩展均有真实呈现}
+
\text{分级分区决策}
+
\text{异常兜底}
+
\text{单一固化镜像稳定演示}
}
\]

## 七、后续讨论时始终回到的几个问题

以后无论讨论一个模块、一段 Verilog、一个演示页面或一项新功能，都先用下面的问题判断它是否值得加入：

1. 它服务的是普通展示、注意提醒、紧急疏散还是故障兜底？
2. 它是否由 FPGA 自己完成，是否符合无额外处理器的限制？
3. 它是否能在同一个固化镜像中和其余功能一起运行？
4. 评委能否从屏幕、声音或状态显示中直接看出它的效果？
5. 它会提升稳定性、实用性或创新性，还是只会增加不必要的复杂度？

如果一个功能不能回答前四个问题，它不应抢占基础项、核心扩展和鲁棒性工作的优先级。项目的目标不是成为功能最杂的 HDMI 演示，而是完成一台逻辑完整、行为可预期、具备明确应用价值的 FPGA 应急信息终端。
