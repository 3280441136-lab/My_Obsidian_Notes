## 教学型学习笔记写作规范

当用户要求讲解、润色或扩展课程笔记时，必须把内容写成一份连贯的教材式教学稿，而不是术语表、公式清单或问答卷。

### 核心要求

- 不要机械地按照用户提问的顺序逐条回答。先判断用户缺失了哪些前置概念，再按照知识依赖关系重新组织内容。
- 不要先给结论、定义或公式，再事后补充解释。每个重要概念都应先说明：
  1. 现实问题或学习困难是什么；
  2. 为什么需要引入这个概念；
  3. 这个概念解决了什么问题；
  4. 它与前面概念有什么关系；
  5. 最后再给出正式定义、公式和计算方法。
- 禁止把多个术语、定理和公式连续堆砌，却不解释它们之间的因果关系、使用动机和实际意义。
- 禁止把正文写成“问题：……答案：……”的问答卷形式。用户的问题应被吸收进一条完整的讲解主线中。
- 如果用户的原始笔记缺少必要前置知识，应主动补齐这些知识，即使这些内容没有出现在用户的原始记录中。
- 如果原笔记只记录了关键词，不要逐个关键词扩写；应根据关键词推断用户正在学习的知识链，并重建一份连贯的教材式说明。
- 每引入一个公式，都必须解释公式中的变量、公式描述的对象、公式为什么长成这样，以及它在什么场景下有用。
- 公式不能代替解释。直觉解释、物理意义、简单例子和公式之间必须相互对应。
- 每个重要结论都应说明适用条件、适用范围以及容易误用的地方。
- 优先使用少量贯穿全文的例子，展示概念如何一步步解决问题，不要为每个结论堆放彼此无关的例题。
- 段落之间必须有清楚的过渡，说明“为什么下一步要引入这个概念”。
- 控制标题数量，标题应体现知识的逻辑层次，而不是把每个术语单独列成一个小节。
- 教学目标是让读者理解“为什么这样定义、为什么这样变换、什么时候使用”，而不只是记住结论。

### 推荐的讲解顺序

对于数学、信号与系统、数字信号处理等抽象课程，优先采用以下教学链条：

1. 先说明研究对象和实际问题；
2. 回顾理解当前内容所必需的前置知识；
3. 从直觉或具体例子发现问题；
4. 说明为什么需要新的概念或工具；
5. 给出正式定义和数学表达；
6. 通过一个简单例子展示公式如何工作；
7. 解释该工具与前面知识的联系；
8. 说明适用条件、局限和常见误区；
9. 最后再给出简短的记忆线索或复习路线。

### 语言要求

- 使用清楚、连续、面向初学者的解释，不假设用户已经理解教材中未说明的概念。
- 专业术语第一次出现时，必须用通俗语言解释其含义和引入原因。
- 可以使用类比，但必须说明类比的边界，不能让类比替代严格定义。
- 避免“显然”“容易看出”“只需记住”等跳过关键推理的表达。
- 如果存在多个约定或不同教材写法，应说明它们的区别，而不是只给出其中一种写法。

若一段内容删除所有公式后就只剩下术语名称和结论，说明解释不充分，必须重新组织。

## 课程笔记状态与新对话工作流

在回答本课程问题前，先读取本文件夹下的 `README.md` 和编号笔记标题，确认已经学过哪些电路类型与知识点。用户来提问时，默认他刚上完一节新课，给出的关键词、讲课脉络和疑问是课堂原始记录；先在对话中按知识依赖关系还原课程内容并解答疑惑，不立即生成笔记。只有用户明确要求整理、保存或形成笔记时，才把对话改写为教材式 Markdown 笔记，按“课次 + 电路类型或主题”命名，并配足 SVG 电路图、等效模型和特性曲线。新笔记完成后更新 `README.md` 的“当前学习进度”。

## SVG 电路图中的数学排版

SVG 图片不会调用 Obsidian 的 LaTeX/MathJax，因此图中文字不能直接粘贴 `$...$`、`R_2s`、`X_Cs`、`Q_L` 等带有原始下划线的公式文本。

- 变量角标必须用 `<tspan baseline-shift="sub">...</tspan>` 或 `<tspan baseline-shift="super">...</tspan>` 明确排版，例如 $R_{2s}$ 应写成 `R<tspan baseline-shift="sub">2s</tspan>`。
- 图中不得把 `_` 当作下标显示；不得让 `Z_in`、`X_Cs`、`Q_L` 之类字符串原样出现在 SVG 文本中。
- 简单的乘积、比值可以使用清晰的行内形式；分式应让分子、分母和横线在视觉上明确，根式应有覆盖线或明确的根号范围。
- 复杂公式不要依赖 Unicode 组合角标猜测渲染结果，应使用 `<tspan>` 控制上下标位置。
- 每次新增或修改 SVG 后，必须用无头浏览器渲染 PNG 检查：角标、分式、根式、元件标签不能重叠、截断或退回原始下划线。
