# 通信原理项目协作约束

## 文件分工

- `README.md`：课程导航、学习进度、阅读路线、英文考试词汇和文件结构的唯一状态来源。
- `AGENTS.md`：约束 Codex 如何讲解、如何写教材式笔记、如何处理全英文考试要求。
- `第N课 主题.md`：已经整理并核对的课程知识。
- `SVG图/`：系统框图、分类图、计算链、波形和频谱图。
- `PPT/`、`作业留档/`：原始课件和作业材料，不自动视为已掌握内容。

不要在 `AGENTS.md` 里复制一份进度表或完整词汇表；状态和词汇索引以 `README.md` 为准。

## 新对话工作流

1. 先读取 `README.md`，再浏览 `第N课*.md` 的文件名、标题和关键图，确认已经学过的章节与符号约定。
2. 把用户提供的课堂关键词、讲课脉络和疑问视为新课原始记录。先补齐缺失的前置概念，再按知识依赖关系还原课程主线。
3. 默认只在聊天中讲解和答疑。只有用户明确要求“整理成笔记”“保存课堂内容”或等价表达时，才创建或修改笔记。
4. 优先归入最合适的已有课次；只有确实形成新的知识单元时，才按国内通信原理教材的知识链新建下一课。
5. 写入后更新 `README.md` 的进度表、阅读路线和英文词汇索引，并检查双链、图片路径、单位和符号。

## 教学型笔记写作规范

### 先建立动机，再给定义

每个重要概念都要按以下顺序展开：

1. 通信中出现的实际问题是什么；
2. 为什么需要引入这个模型、分类或指标；
3. 它解决了什么判断或计算问题；
4. 它与前面的系统模型、信息度量或性能指标有什么关系；
5. 最后才给正式定义、公式和计算方法。

不能把术语、定理和公式连续堆砌。用户的问题要融入完整讲解主线，不能写成问答卷。

### 公式必须解释

每引入一个公式，必须说明：

- 公式描述的是消息、信息、码元、比特、带宽还是错误概率；
- 每个变量、角标、单位和上下标的含义；
- 为什么公式长成这样，概率、时间或带宽怎样进入关系；
- 在模拟/数字、基带/带通、单条消息/信源平均等不同场景下如何理解；
- 适用条件和容易混淆的地方。

尤其要区分：

- 单条消息的 information content 与信源 entropy；
- symbol rate 与 bit rate；
- bandwidth 与 bandwidth efficiency；
- symbol error rate 与 bit error rate (BER)；
- 有效性与可靠性的评价对象。

公式不能代替解释。每个结论都要对应直觉、单位检查和简单例子。

### 推荐讲解顺序

1. 研究对象和实际通信任务；
2. 必要的系统模型和概率知识；
3. 从例子发现旧概念不足；
4. 说明为什么需要新的指标；
5. 给出定义、英文术语和数学表达；
6. 用一个贯穿性例子展示计算；
7. 解释单位、数量级和物理意义；
8. 说明适用条件、局限和易错点；
9. 给出中英文复习路线。

标题体现知识层次，不要每个术语单列一节。段落之间要说清为什么下一步要引入新概念。

### 语言要求

- 使用清楚、连续、面向初学者的解释，不假设读者已经掌握教材外概念。
- 不使用“显然”“容易看出”“只需记住”等跳步表达。
- 教材或课堂若存在不同符号、单位约定或分类依据，必须说明差异。
- 类比只帮助建立直觉，必须说明边界。

## 全英文考试的专门要求

本课程考试为全英文，中文讲解不能取代英文术语训练。整理和复习时必须遵守：

1. **首次出现原则**：重要概念第一次出现时写成“中文（English term）”或“English term（中文）”，之后可按上下文使用其中一种，但同一笔记保持一致。
2. **符号—术语对应**：公式定义中同时说明英文变量名，例如 $R_s$ 为 symbol rate，$R_b$ 为 bit rate，$H(X)$ 为 entropy，$P_e$ 为 probability of error。
3. **英文题干识别**：遇到 derive、express、calculate、determine、compare、explain、show that 等设问动词，要按其要求组织答案，不能把计算题只写成概念解释。
4. **英文单位与缩写**：掌握 baud、bit/s、Hz、SNR、BER、FDM、TDM、WDM、CDM 等标准写法；不要把 baud 与 bit/s 混用。
5. **每课词汇出口**：新笔记结尾设置简短的“English Exam Terms”表，包含 term、symbol、meaning、common question wording；同步补充到 `README.md` 的总索引。
6. **复习检测**：重要部分应能够完成三种切换——中文释义到英文术语、英文题干到解题动作、符号到变量含义。
7. **不机械翻译**：英文术语要放在系统模型、计算关系和适用条件中理解，不能只列单词。

## Markdown、数学与软件约束

- 输出或修改 Obsidian Markdown 文件时：行内公式使用 `$...$`，独立公式使用 `$$...$$`。
- Codex 聊天回复中：行内公式使用 `\(...\)`，独立公式使用 `$$...$$`。
- 数学内容必须使用正确 LaTeX，不用纯文字或 Unicode 数学记号替代公式。
- 图片放入 `SVG图/`，使用 Obsidian 可解析的相对路径。
- Keil、ESP 项目不代为编译。
- 不擅自删除课件、作业、SVG 图或历史笔记。
