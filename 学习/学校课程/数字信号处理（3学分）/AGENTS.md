# 数字信号处理项目协作约束

## 文件分工

- `README.md`：课程导航、学习进度、知识主线和文件结构的唯一状态来源。
- `AGENTS.md`：约束 Codex 如何讲解、如何写教材式笔记、如何修改文件。
- `NN 第N课 主题.md`：已经整理并核对的主笔记。
- `assets/`：频谱、波形、收敛域、系统框图等图片资源。
- `_原始汇总/`：拆分前的历史综合稿，只用于追溯来源。

不要在 `AGENTS.md` 中复制一份学习进度表；状态以 `README.md` 为准。

## 新对话工作流

1. 先读取 `README.md`，再浏览主笔记文件名、标题和图片，确认已经覆盖到哪个知识单元。
2. 将用户给出的课堂关键词、讲课脉络和疑问视为一节新课或旧课延伸的原始记录。
3. 先判断缺失的前置概念，再按知识依赖关系重排讲解，不按关键词逐条机械扩写。
4. 默认只在聊天中讲解。只有用户明确要求“整理成笔记”“保存课堂内容”或等价表达时，才创建、合并或修改笔记。
5. 优先归入最合适的已有课次；只有形成新的知识单元时才新建下一课。DFT、FFT、滤波器结构和设计应分别成课。
6. 写入后更新 `README.md`，并检查编号连续性、双链、符号约定和图片路径。

## 教学型笔记写作规范

### 从问题和动机出发

每个重要概念都要先说明：

1. 原信号或系统中出现了什么问题；
2. 为什么时域描述不够；
3. 新工具解决了什么问题；
4. 它与前面的序列、卷积、频率、采样或极零点有什么关系；
5. 最后才给定义、变换对和计算方法。

不能把定义、性质和公式连续堆砌。用户的问题必须被吸收进一条完整教学主线，不能写成问答卷。

### 公式必须解释

每引入一个公式，必须解释：

- 公式描述的信号、系统或变换是什么；
- 自变量、积分/求和变量、上下标和收敛条件；
- 为什么采用这种定义，关键变量为什么出现在那里；
- 时域、频域、复频域之间怎样对应；
- 适用条件、周期性、收敛域和常见误用。

直觉、简单序列例子、图形和公式必须相互对应。不同教材在归一化频率、傅里叶核指数符号或 ROC 边界上的约定可能不同，遇到时必须明确本笔记采用哪一种。

### 推荐讲解顺序

1. 研究对象和实际问题；
2. 必要的序列、线性、时不变和复指数知识；
3. 从具体例子发现旧工具的不足；
4. 说明为什么需要新的表示；
5. 给正式定义和数学表达；
6. 用一个贯穿性简单序列演示计算；
7. 解释与已有工具的联系；
8. 说明适用条件、局限和误区；
9. 给出复习路线。

标题体现知识层次，不要每个术语单列一节。段落之间要说清下一步为什么这样展开。

### 语言要求

- 面向初学者连续解释，不假设教材外概念已经掌握。
- 术语第一次出现时说明含义和引入原因。
- 避免“显然”“容易看出”“只需记住”等跳步表达。
- 类比必须说明边界，不能代替严格定义。
- 删除公式后若只剩术语和结论，说明解释不足，必须重写。

## 课程专属符号与概念规则

- 离散时间序列统一写成 $x[n]$，不要用 $x(t)$ 表示离散样本。
- 明确区分数字角频率 $\omega$（通常以 rad/sample 为单位）与物理频率 $f$；不要混用“频率”而不说明单位。
- 明确区分 DTFT、DFT 与 Z 变换：DTFT 的自变量连续且频谱周期，DFT 只取有限个频点，Z 变换还要讨论收敛域。
- 提到 ROC 时，要说明为什么极点、单位圆和因果性/稳定性判断需要它，不能只写边界。
- 采样内容必须区分理想采样、有限长序列和实际采样近似；混叠与泄漏不能混为一谈。
- 图形应帮助观察“时域变化怎样反映到频域、复频域”。优先使用频谱图、极零点与 ROC 图、系统框图和变换对应图。

## Markdown、数学与软件约束

- 输出或修改 Obsidian Markdown 文件时：行内公式使用 `$...$`，独立公式使用 `$$...$$`。
- Codex 聊天回复中：行内公式使用 `\(...\)`，独立公式使用 `$$...$$`。
- 数学内容必须使用正确 LaTeX，不用纯文字或 Unicode 数学记号替代公式。
- 图片放入 `assets/`，在 Obsidian 中使用 `![[assets/...]]` 或可解析的相对路径。
- Keil、ESP 项目不代为编译。
- 不擅自删除原始汇总、课件、作业或历史图片。
