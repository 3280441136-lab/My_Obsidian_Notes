## 教学型学习笔记写作规范

当用户要求讲解、润色或扩展课程笔记时，必须把内容写成一份连贯的教材式教学稿，而不是术语表、公式清单或问答卷。

### 核心要求

- 不要机械地按照用户提问的顺序逐条回答。先判断用户缺失了哪些前置概念，再按照知识依赖关系重新组织内容。
- 不要先给结论、定义或公式，再事后补充解释。每个重要概念都应先说明：
  1. 现实问题或学习困难是什么；
  2. 为什么需要引入这个概念；
  3. 这个概念解决了什么问题；
  4. 它与前面概念有什么关系；
  5. 最后再给出正式定义、公式和计算方法。
- 禁止把多个术语、定理和公式连续堆砌，却不解释它们之间的因果关系、使用动机和实际意义。
- 禁止把正文写成“问题：……答案：……”的问答卷形式。用户的问题应被吸收进一条完整的讲解主线中。
- 正文标题必须使用教材式陈述标题，直接标明本节研究对象或知识内容；禁止使用“为什么……”“怎样……”“什么是……”等提问式标题组织课程笔记。
- 组织笔记前，先参照国内教材的经典章节体系确定知识依赖和层级，再安排“基本模型或定义—核心规律与推导—分析或设计方法—结论、适用条件与易错点”；不得按照聊天提问顺序拼接正文。
- 如果用户的原始笔记缺少必要前置知识，应主动补齐这些知识，即使这些内容没有出现在用户的原始记录中。
- 如果原笔记只记录了关键词，不要逐个关键词扩写；应根据关键词推断用户正在学习的知识链，并重建一份连贯的教材式说明。
- 每引入一个公式，都必须解释公式中的变量、公式描述的对象、公式为什么长成这样，以及它在什么场景下有用。
- 公式不能代替解释。直觉解释、物理意义、简单例子和公式之间必须相互对应。
- 每个重要结论都应说明适用条件、适用范围以及容易误用的地方。
- 优先使用少量贯穿全文的例子，展示概念如何一步步解决问题，不要为每个结论堆放彼此无关的例题。
- 段落之间必须有清楚的过渡，说明“为什么下一步要引入这个概念”。
- 控制标题数量，标题应体现知识的逻辑层次，而不是把每个术语单独列成一个小节。
- 教学目标是让读者理解“为什么这样定义、为什么这样变换、什么时候使用”，而不只是记住结论。

### 推荐的讲解顺序

对于数学、信号与系统、数字信号处理等抽象课程，优先采用以下教学链条：

1. 先说明研究对象和实际问题；
2. 回顾理解当前内容所必需的前置知识；
3. 从直觉或具体例子发现问题；
4. 说明为什么需要新的概念或工具；
5. 给出正式定义和数学表达；
6. 通过一个简单例子展示公式如何工作；
7. 解释该工具与前面知识的联系；
8. 说明适用条件、局限和常见误区；
9. 最后再给出简短的记忆线索或复习路线。

### 语言要求

- 使用清楚、连续、面向初学者的解释，不假设用户已经理解教材中未说明的概念。
- 无论在 Codex 聊天中讲课、答疑，还是整理 Markdown 笔记，叙述都应像教师带着学生沿问题逐步推导：先让读者看到现象、困难或矛盾，再自然引出概念、公式和方法，并用过渡句说明下一步的必要性。
- 保持教材式严谨，但避免“本文将……”“综上所述……”等官方报告腔和空泛套话。正文可以用少量自然设问引导思考，但必须立即融入连续讲解，不能写成提问与答案的清单。
- 专业术语第一次出现时，必须用通俗语言解释其含义和引入原因。
- 可以使用类比，但必须说明类比的边界，不能让类比替代严格定义。
- 避免“显然”“容易看出”“只需记住”等跳过关键推理的表达。
- 如果存在多个约定或不同教材写法，应说明它们的区别，而不是只给出其中一种写法。

若一段内容删除所有公式后就只剩下术语名称和结论，说明解释不充分，必须重新组织。

### Mermaid 本课概要

- 每篇按课次编号的课程笔记都必须在一级标题之后、其他导语或正文之前设置 `## 本课概要`，并紧接一个 Mermaid `mindmap` 代码块。
- 概要必须是以本课主题为根节点的知识思维导图，通常设置 3 至 5 个一级分支，并在需要时继续展开二级分支，呈现核心概念、关键关系、分析或计算方法、应用以及易错点。
- 知识树必须先按国内教材的经典体系重新归类，再映射到正文层级；一级分支对应稳定、互不混杂的知识模块，顺序与正文主线一致。
- 同级节点必须采用同一分类依据；父子节点必须具有明确的总分、分类、组成、性质或方法关系。禁止把概念、例题、结论和易错点随意并列，禁止为了凑分支而重复或拆碎知识点。
- 分支必须反映知识结构，不能把课程错误地画成单条线性流程，也不能只是机械抄录正文目录或仅作装饰。若重点是步骤、因果或状态变化，应另用 `flowchart` 表达，不得扭曲知识树。
- 节点文字应使用教材式陈述短语，禁止使用问答句；图中术语、层级和顺序必须与正文一致。
- Mermaid 节点内不写 LaTeX 公式；涉及变量和公式时用简短中文概念概括，严格数学表达放在正文中，以保证 Obsidian 稳定渲染。
- 新建笔记时必须添加该思维导图；修改既有课程笔记时，也要检查并补齐或同步更新概要。


## 课程学习档案与新对话工作流

### 这个文件夹是做什么的

这是“数字信号处理（3学分）”的长期学习笔记库。用户在课堂上可能只记录关键词、讲课脉络和疑问；新对话中的任务通常是先根据这些材料还原课堂内容并解答疑惑，只有用户明确要求“整理成笔记”时，才把对话内容写入 Markdown 笔记文件。

每次进入本文件夹开始新对话时，必须先执行以下检查：

1. 读取本文件，了解当前学习进度和笔记划分。
2. 浏览课程文件夹中的 Markdown 文件与 `assets/`，确认实际已有内容；不要只依赖本文件中的摘要。
3. 将用户本次给出的课堂关键词、讲课脉络和疑问视为“新一课或新知识片段”的线索，先还原它与已有知识的依赖关系。
4. 在聊天中完成讲解和答疑；除非用户明确要求整理笔记，否则不要新增、覆盖或重排笔记文件。

### 新一课在聊天中的处理方式

当用户带着课堂关键词、讲课脉络和疑问来提问时：

1. 先判断这些内容属于已有哪一课的延伸，还是需要建立新课。
2. 找出用户缺了哪些前置概念，再按知识依赖关系重排讲解顺序，不要机械地按关键词逐条回答。
3. 将老师的讲课脉络还原成连续主线：先说明问题和动机，再解释概念、给出公式、举例、说明联系与适用条件，最后回答具体疑惑。
4. 如果用户的问题暴露出常见误解，应明确比较“直觉说法、严格定义、适用边界”，不要只给结论。
5. 对公式中的变量、对象、来源和用途逐项解释；不要把公式堆成清单。
6. 默认把“关键词 + 讲课脉络 + 多个疑问”视为一次新课学习记录，但若用户明显是在复习旧课或讨论作业，应按实际意图处理。

### 何时以及怎样写成笔记

只有用户明确要求整理对话内容形成笔记时，才修改或创建笔记文件。整理时必须遵守：

- 先按内容划分为若干个课次文件，不要把所有知识继续耦合在一个大文件中。
- 优先归入 `NN 第N课 主题.md` 中最合适的一课；只有内容确实形成新的知识单元时才新建下一课。
- 文件名与课次要连续、可排序，主题名应描述知识单元，而不是照抄用户问题。
- 一篇笔记应是一条连贯的教材式教学主线，不是聊天记录、术语表或问答卷。
- 若同一主题已有笔记，应合并、去重、补足过渡；不要创建内容重复的平行文件。
- 每篇笔记都要有简短的“本课定位”和结尾的“小结、适用条件、常见误区或下一步”，并链接前后相关笔记。
- 图形应服务理解，而不是装饰。根据内容配置足够数量的 SVG 图、流程框图、信号波形图、频谱图、概念对比图；涉及电路或实现结构时补充电路图或系统框图；同时使用表格归纳、易混概念对照和典型计算流程。
- 图片统一放在 `assets/` 下，按主题使用子目录，并在 Obsidian Markdown 中用 `![[assets/...]]` 嵌入。
- 输出或修改 Obsidian Markdown 文件时，行内公式使用 `$...$`，独立公式使用 `$$...$$`。
- Markdown 表格的公式中不得使用会被识别为分栏符的裸竖线：绝对值统一写成 `\lvert\cdot\rvert`，条件分隔符使用 `\mid`；过长或结构复杂的公式应移到表格外独立排版。
- 在 Codex 聊天回复中，行内公式使用 `\(...\)`，独立公式使用 `$$...$$`，不要用纯文字或 Unicode 数学记号代替公式。
