## 没有文件系统时的 Flash 访问

文件系统就是：**把 Flash 的一块区域变成"像 U 盘一样能按文件名存取东西"的空间。**

没有文件系统时，Flash 更像一排原始储物格：

```text
地址 0x310000 放 1 个字节
地址 0x310001 放 1 个字节
地址 0x310002 放 1 个字节
...
```

你要自己记住每个数据放在哪个地址，读写很麻烦。

---

## 有了文件系统之后

有文件系统后，就可以按文件名访问：

```text
/index.html
/config.json
/logo.png
/music.wav
/data/log.txt
```

程序里可以按文件名打开：

```c
FILE *f = fopen("/spiffs/config.json", "r");
```

这就像电脑上打开 `C:\Users\xxx\config.json` 一样。

---

## 为什么嵌入式需要文件系统

因为很多东西不适合直接写死在程序代码里。

比如做一个带网页配置页面的 ESP 设备，Flash 里可能要放：

```text
index.html
style.css
script.js
logo.png
```

如果没有文件系统，你就要把这些文件转成 C 数组：

```c
const unsigned char index_html[] = {0x3c, 0x68, 0x74, ...};
```

这很难维护。有文件系统后，可以直接把网页文件放进去，程序运行时读取。

常见用途：

| 用途 | 例子 |
|---|---|
| 网页文件 | `index.html`、`style.css`、`app.js` |
| 图片资源 | `logo.png`、图标 |
| 配置文件 | `config.json` |
| 日志文件 | `log.txt` |
| 音频文件 | `beep.wav` |
| 设备数据 | 传感器历史记录 |

## NVS 和文件系统的区别

```text
NVS：适合存少量键值数据
文件系统：适合存文件和较大的结构化数据
```

具体选择：

```text
Wi-Fi 名称：适合 NVS
Wi-Fi 密码：适合 NVS
设备编号：适合 NVS
用户设置：适合 NVS 或 config.json
网页文件：适合文件系统
图片：适合文件系统
日志：适合文件系统
```

NVS 像一个小本子：

```text
wifi_ssid = "MyWiFi"
volume = 80
brightness = 50
```

文件系统像一个文件夹：

```text
/index.html
/logo.png
/log.txt
/config.json
```

## SPIFFS / LittleFS / FATFS 对比

ESP-IDF 里常见的文件系统：

| 文件系统 | 特点 |
|---|---|
| SPIFFS | ESP 里很常见，简单易用 |
| LittleFS | 比 SPIFFS 更现代，掉电可靠性更好 |
| FATFS | 更像 U 盘/SD 卡里的 FAT 文件系统，兼容性好 |

初学者可以先记住：SPIFFS 够用就先用 SPIFFS，对可靠性要求高考虑 LittleFS，需要和电脑互拷文件考虑 FATFS。

## 实际例子：网页控制 LED

做一个 ESP32 网页控制 LED 的项目。

程序负责控制 LED：

```text
app 程序分区：
main.c
wifi.c
led.c
web_server.c
```

网页资源放在文件系统：

```text
文件系统分区：
/index.html
/style.css
/script.js
```

运行时流程：

```text
浏览器访问 ESP
    ↓
ESP 程序收到请求
    ↓
从文件系统读取 index.html
    ↓
发给浏览器
```

这样 C 程序和网页文件就分开管理了。

## 什么时候不需要文件系统

不是所有项目都需要文件系统。如果只是：

- 点灯
- 读按键
- 控制电机
- 简单传感器采集

可能完全不需要。但如果项目要存网页、图片、日志、配置文件，就很有用了。

```text

NVS 是小本子存键值，文件系统是文件夹存大文件。
网页图片用文件系统，Wi-Fi 密码用 NVS。
```
