# 声学学习项目约定

当用户说“继续声学学习”“查看学习项目”或讨论本目录中的声学资料时，先阅读：

1. `README.md`
2. `00_项目状态.md`
4. `08_交接日志/` 中日期最新的日志（如存在）

工作原则：

- 用户自己决定每天学到哪里；不要创建按天、按周或按时长的学习计划。
- 以“理解声学超构材料、线性与非线性声学”为目标选择声学基础和数学物理方法内容；习题只用于验证理解，不把笔记写成应试提纲。
- 对话中的解释优先于笔记。必须先把问题讲清楚，再将已确认的理解、待解问题和双语术语更新到项目笔记中。
- 用户明确说“写交接日志”、准备开新对话或上下文不足时，才创建交接日志并更新项目状态；不要为每一次对话自动写日志。
- 输出 Markdown 笔记时，面向 Obsidian：行内数学使用 `$...$`，独立公式必须使用 `$$` 块。需要空间关系、波形或结构图时，创建或更新 `10_图示/` 中可嵌入的 SVG；只有交互确有价值时才创建 HTML。禁止 ASCII 绘图。
- Codex 聊天回复保留行内数学公式：行内公式使用 LaTeX 的 `\(...\)`，独立公式使用 `$$...$$`。不要用 Unicode 数学记号替代公式。输出 Obsidian Markdown 文件时，仍遵循上一条规定，行内公式使用 `$...$`，独立公式使用 `$$...$$`。

## 教学型学习笔记写作规范

当用户要求讲解、润色或扩展课程笔记，输出笔记md时，必须把内容写成一份连贯的教材式教学稿，而不是术语表、公式清单或问答卷。

### 核心要求

- 不要机械地按照用户提问的顺序逐条回答。先判断用户缺失了哪些前置概念，再按照知识依赖关系重新组织内容。
- 不要先给结论、定义或公式，再事后补充解释。每个重要概念都应先说明：
  1. 现实问题或学习困难是什么；
  2. 为什么需要引入这个概念；
  3. 这个概念解决了什么问题；
  4. 它与前面概念有什么关系；
  5. 最后再给出正式定义、公式和计算方法。
- 禁止把多个术语、定理和公式连续堆砌，却不解释它们之间的因果关系、使用动机和实际意义。
- 禁止把正文写成“问题：……答案：……”的问答卷形式。用户的问题应被吸收进一条完整的讲解主线中。
- 如果用户的原始笔记缺少必要前置知识，应主动补齐这些知识，即使这些内容没有出现在用户的原始记录中。
- 如果原笔记只记录了关键词，不要逐个关键词扩写；应根据关键词推断用户正在学习的知识链，并重建一份连贯的教材式说明。
- 每引入一个公式，都必须解释公式中的变量、公式描述的对象、公式为什么长成这样，以及它在什么场景下有用。
- 公式不能代替解释。直觉解释、物理意义、简单例子和公式之间必须相互对应。
- 每个重要结论都应说明适用条件、适用范围以及容易误用的地方。
- 优先使用少量贯穿全文的例子，展示概念如何一步步解决问题，不要为每个结论堆放彼此无关的例题。
- 段落之间必须有清楚的过渡，说明“为什么下一步要引入这个概念”。
- 控制标题数量，标题应体现知识的逻辑层次，而不是把每个术语单独列成一个小节。
- 教学目标是让读者理解“为什么这样定义、为什么这样变换、什么时候使用”，而不只是记住结论。

### 推荐的讲解顺序

对于数学、信号与系统、数字信号处理等抽象课程，优先采用以下教学链条：

1. 先说明研究对象和实际问题；
2. 回顾理解当前内容所必需的前置知识；
3. 从直觉或具体例子发现问题；
4. 说明为什么需要新的概念或工具；
5. 给出正式定义和数学表达；
6. 通过一个简单例子展示公式如何工作；
7. 解释该工具与前面知识的联系；
8. 说明适用条件、局限和常见误区；
9. 最后再给出简短的记忆线索或复习路线。

### 语言要求

- 使用清楚、连续、面向初学者的解释，不假设用户已经理解教材中未说明的概念。
- 专业术语第一次出现时，必须用通俗语言解释其含义和引入原因。
- 可以使用类比，但必须说明类比的边界，不能让类比替代严格定义。
- 避免“显然”“容易看出”“只需记住”等跳过关键推理的表达。
- 如果存在多个约定或不同教材写法，应说明它们的区别，而不是只给出其中一种写法。

若一段内容删除所有公式后就只剩下术语名称和结论，说明解释不充分，必须重新组织。
