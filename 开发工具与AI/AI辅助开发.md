## 为什么用 AI 辅助开发

嵌入式开发中 AI 工具的价值：

```text
代码理解：看不懂的外设库代码，让 AI 逐行解释
笔记整理：把学习对话中的知识点整理成结构化笔记
代码审查：找 bug、检查内存泄漏、分析竞态条件
架构设计：帮你分析模块耦合、设计事件总线
文档生成：从代码生成注释和说明文档
```

## 工具概览

| 工具 | 类型 | 适用场景 |
|---|---|---|
| Claude | 对话式 AI | 代码分析、知识整理、架构设计 |
| GitHub Copilot | IDE 插件 | 代码补全、函数生成 |
| ChatGPT | 对话式 AI | 通用问答、概念解释 |

## 使用场景

### 学习新外设

把数据手册的关键信息 + 库函数贴给 AI，让它帮你梳理初始化流程。

### 重构代码

把当前代码贴给 AI，描述耦合问题，让它给出解耦方案（参见 [[../02.嵌入式系统/嵌入式设计模式/EventBus事件总线架构]]）。

### 调试

把异常现象 + 相关代码贴给 AI，让它帮你定位问题。

### 写笔记

把学习对话导出，让 AI 帮你整理成结构化笔记（这就是本知识库大部分笔记的来源）。

---

## 注意事项

```text
不要贴完整的项目代码（安全和隐私）
AI 的建议需要验证，不能盲信
嵌入式底层细节 AI 可能不准确（尤其是国产芯片）
最终决策权在自己手上
```

## 常用 Prompt 模板

### 代码解释

```
请逐行解释这段代码在做什么，重点是每个 GD32 库函数参数的含义。
```

### 架构分析

```
分析这段代码的模块耦合情况，给出解耦建议。
```

### 笔记整理

```
把上面的对话整理成结构化笔记，包含目录、人话解释、代码示例。
```
